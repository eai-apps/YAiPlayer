## Цель
YAiPlayer — IPTV-плеер: Android TV, Android телефон/планшет, Web. M3U/M3U8, Stalker/Ministra, Xtream, EPG, вход в аккаунт, PIN/QR привязка ТВ, синхронизация через Cloudflare Worker + D1.
Android — открытая лицензия GPL-3.0 (основа OwnTV), чтобы можно было монетизировать в Google Play. Web: решено (05.11.2026) — сайт на Pages БЕЗ плеера: вход, профиль, кабинет с плейлистами/Stalker/EPG и синхронизацией; код StreamVault не используем (пишем заново).

## Отдельная будущая цель (НЕ в этой папке)
Свой продукт на своём ядре под другим названием и с закрытой собственной лицензией. Из GPL-кода OwnTV и из кода StreamVault туда ничего не переносить. Только свой код и идеи.

## Правила
1. В эту папку — только проверенное сборкой/запуском. Каждая запись в журнале: что, кто, как проверено.
2. Сборки и запуск на устройстве разрешены (в старом проекте они были запрещены — из-за этого блоки 09.x ходили по кругу).
3. Один короткий HANDOFF вместо сотен отчётов. Не плодить файлы-отчёты.
4. Секреты, ключи подписи, пароли, провайдерские конфиги — не писать в файлы и репозиторий.
5. Radio/local/DSP/iOS/billing — не в этом проекте.
6. Владелец не программист: объяснять по-русски, ручные шаги — с полным путём (сайт → раздел → кнопка).
7. Код пишет помощник (Antigravity/DeepSeek) по файлу задания, Claude/Codex проверяют. Результат помощника сначала во временной папке TempCode на ПК владельца.

## Stalker-портал провайдера (Ministra) — разбор
- Ministra 5.6.1, вход по логину/паролю (`auth_url=auth_simple.php`), `enable_device_id_validation=true`, сторонние приложения не блокируются, формат MAC не проверяется, защита nginx закрывает только админку.
- В логах доступа видно: handshake 200 → портал вызывает auth_simple.php → `do_auth` 200 (285 байт) → дальше `get_profile` НЕ вызывается, т.е. приложение обрывает вход после do_auth (при `device_id=` и `device_id2=` пустых). Причина пока неизвестна: в версии 1d в сообщение об ошибке выводится ответ портала на do_auth.
- Файлы оператора лежат только у владельца на ПК (содержат секреты, в репозиторий НЕ класть).

Как включить: `{"enforce": true, "min_version": "2.0.60", "block_at": "2026-12-05", "update_url": "…"}`; закоммитить в main.

- после block_at (или если block_at пуст) → полноэкранная блокировка, кнопка «Обновить сейчас» (штатный OTA) и «Проверить снова».
Чтобы отключить — `enforce: false`. В новость для пользователей НЕ писать (служебная функция). Работает только в версиях, где код уже есть: чем раньше он выйдет, тем больше людей под защитой.

### Нумерация версий (07.11.2026)
С 07.11.2026 релизы называются **3.0.N** (первый — 3.0.1, затем 3.0.2…): N = число уже выпущенных тегов `v3.0.*` + 1, считается в `release.yml` (шаг «Compute version»). `versionCode` по-прежнему = номер запуска workflow (растёт всегда). Последний релиз старой линии — v2.0.47 (первая версия с Version gate). Для блокировки старых версий ставить `min_version` = первая 3.0.x, но только когда она уже опубликована.

## Аудит SettingsTransferServer (10.11.2026, Codex)

Статический аудит кода, сетевой тест не проводился. ТВ запускает временный HTTP-сервер `ServerSocket(0)` на случайном порту, привязанный ко всем интерфейсам; любой достигающий порт клиент может подключиться. Экспорт и импорт требуют случайный 12-символьный токен в URL/QR, отдельного PIN нет; таймаут по умолчанию 5 минут, после передачи остановка откладывается на 2 секунды. HTTP не шифрует токен и данные. `tokenConsumed` не используется для запрета повторной передачи: до остановки возможны повторные запросы с токеном. Лимит входящего файла 5 МиБ.

`SettingsBackupManager.exportJson` экспортирует профили, названия и типы плейлистов, EPG-источники вместе с URL, настройки, пользовательские категории и данные. Пароли и URL плейлистов намеренно исключены, но URL EPG может содержать секреты; содержимое резервной копии следует считать конфиденциальным. Сервер принимает JSON для последующего подтверждения восстановления. HTML формы и успеха жёстко заданы по-русски, заголовок страницы и ошибки сервера на английском, поэтому локализация неполная. Рекомендуется отдельно проработать защищённый транспорт, однократное использование токена, ограничение интерфейса и локализацию; крупные изменения не выполнялись.

Метки `test/list-epg` изучены по коммиту `b216642`: он фиксирует нажатие «Назад», начало выхода и остановку движков. В текущую ветку добавлены собственные метки начала/конца выхода и очереди остановки mpv; `OwnTVPerf` доступен только в сборке с `devTools`. ### Задание 2 — реализация и границы проверки
- Новый `EpgGapFill` последовательно читает источники пользователя (в их порядке) перед встроенными. Приоритет чтения явно отделяет встроенные в конец. XMLTV плейлиста регистрируется до постановки фонового прохода; Stalker без XMLTV использует собственную программу первым.
- Перед каждым резервным источником повторная индексированная проверка ближайших 24 часов и отдельно прошедшего окна архива (1–14 дней) во всех профилях. «Есть программа» означает хотя бы одну пересекающую окно передачу, а не сплошное покрытие всех суток. Сдвиг EPG учитывается. Сеть скачивает XMLTV целиком (сервер не предоставляет выборку каналов); в базу из конкретного кеша попадают только выбранные каналы/пустые окна. Пустой источник повторно в этом проходе не вызывается. Ошибки источников изолированы, отмена пробрасывается.
- Ручные привязки не переписываются: резервные передачи сохраняются под существующим ключом канала, оставаясь ниже пользовательских источников. Запись EPG: транзакции по 250 строк с yield, `epg_commit`, индексы не снимаются при начальной загрузке. `epg_gap_pass` отмечает время прохода.
