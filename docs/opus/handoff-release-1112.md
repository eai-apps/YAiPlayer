## Ветки и порядок слияния
1. `test/atv-remote` — пульт всей приставки (Android TV Remote v2): телефон сам находит приставку, код один раз, D-pad/Домой/громкость/текст.
2. `test/tv-optimizer-adb` — «Ускорь телевизор» (настоящий ADB, 468 моделей, откат, лаунчер собирается в CI). Плитка видна только в debug (`TV_OPTIMIZER_READY = BuildConfig.DEBUG`).
3. `test/refresh-queue-series` — одна очередь обновлений вместо четырёх, честный % EPG, параллельная программа Stalker, логотипы из EPG, страница сериала на ТВ («Сезон N ▾», серии сеткой), выбор сезона на телефоне.
4. `test/owner-answers-1112` — построена ПОВЕРХ п.3 (п.3 входит в неё целиком). Телефон: очередь автообновления останавливается при сворачивании/выключении экрана и продолжается при возврате; фоновая проверка только на зарядке и только для активного профиля; понедельничная докачка Stalker на телефоне тоже только на зарядке. Сливать после п.3 (или вместо него). Сливать только при зелёных Build/Tests — на момент передачи CI ещё шёл.
5. `test/radio-play-flavor` — радио в плеере (ТВ: пункт над «Телеканалами» и плитка на экране профилей; телефон: плитка и кнопка), синхронизация избранного с аккаунтом сайта YAiPlay Radio. ОДНА сборка с радио, имена вариантов и APK как раньше (`assembleStandardDebug/Release`), самообновление по прежней ссылке. Play-сборка не выпускается (на будущее: `-Powntv.playStore=true`, проверка — workflow «Play-store build check»). Название магазина нигде не писать.
6. `test/opus-batch-report` — только документы (`docs/opus/report-opus-batch.md`, этот файл, запись в HANDOFF).

Конфликты ожидаются только в `HANDOFF.md`, `.github/workflows/tests.yml`, `build.yml`, `release.yml`: оставлять изменения обеих сторон (в tests.yml — все `--tests`; шаги сборки лаунчера из п.2 сохранить; в release.yml вариант `assembleStandardRelease` и путь `apk/standard/release`). После слияния всех веток дождаться зелёных Build и Tests на main, затем выпуск как обычно.
