# Codex: вход в проект YAiPlayer (читать первым)

Репозиторий: eai-apps/YAiPlayer (открытый, GPL-3.0, основа OwnTV). Клиенты: `clients/android-tv`, `clients/android-mobile`, общее ядро `clients/owntv-core`. Владелец: начинающий, Германия. Отвечай ему **по-русски, мужской род**, объясняй точными путями («открой сайт…, слева…, нажми…»). Ключи и пароли он вносит сам, никогда не проси их прислать.

## Порядок чтения
1. `HANDOFF.md` в корне (правила, журнал работ, раздел «Кто что делает сейчас»).
2. `docs/CHECKLIST.md` (что сделано, что в очереди, правила в разделе 7).
3. Свои задания: `docs/codex/task-1-operator-fixes.md`, затем `task-2-epg-core.md`, затем `task-3-channels-and-live.md`, затем `task-4-remote-and-optimizer.md` (части A и B запускаются отдельно). Делай ТОЛЬКО то задание, которое названо в сообщении владельца, в одной ветке (или в ветках, указанных в задании). Закончил: напиши короткий итоговый отчёт (что сделано, ветки, что проверить) и ОСТАНОВИСЬ. К следующему заданию не переходи, владелец запустит его в новом чате. Готовые промпты: `docs/codex/PROMPTS.md`.

## Правила работы
- Паритет: всё, что видно пользователю, делается и в ТВ-приложении, и в мобильном (кроме явно помеченного «только телефон»).
- ТВ: компоненты `androidx.tv.material3`, масштаб `.mpx` из `tv.own.owntv.ui.theme`; мобильное: `material3`. Перед использованием любого компонента сверь его сигнатуру в исходнике, ничего не придумывай (прошлые ветки Антигравити ломались именно на выдуманных методах).
- Общие строки в `clients/owntv-core/core/src/main/res/values*/strings_*.xml` (en, ru, de), пакет ресурсов `tv.own.owntv.core.R`. Для строк работает i18n-храповик: `clients/owntv-core/tools/i18n/` (verify, prune-safe, classify-safe), список `safe_literals.txt` в каждом модуле.
- Локально приложение собрать нельзя (нет Android SDK): проверка только через GitHub Actions. Ветка от свежего `origin/main`, имя `test/<тема>`, push без force. Смотри CI: `gh run list --branch <ветка> --json name,status,conclusion`; ошибки: `gh run view <id> --log-failed | grep " e: "`. Нужны зелёные «Build» и «Tests». Если GitHub-CLI у тебя нет, проси владельца прислать лог.
- Слияние в main делаю я (Claude) или владелец: ветка в main только через ff-only после зелёного CI. Сам в main не пушь.
- `docs/WHATS_NEW.md`: только пользовательские пункты по-русски, одной строкой, без названий скрытых источников EPG. Не повторять уже выпущенное.
- Новый код пиши своими пакетами и файлами с заголовком `// Copyright (C) 2026 YAiPlayer authors. Original code, written for YAiPlayer.` и перечисляй новые файлы в `HANDOFF.md` (чтобы их можно было переиспользовать в закрытом ядре).
- Не трогай подпись, релизные workflows и `docs/legal`.
- В отчёте пиши только то, что реально сделано и проверено CI. Не выдумывай. Если что-то не сделал, так и напиши.

## Что нельзя делать без владельца
Менять публичные адреса, секреты, Telegram-бота, Cloudflare-настройки. Секреты и ключи не коммитить.

У Claude на этой неделе почти нет лимитов, поэтому Codex делает все четыре задания (примерно два дня; если не успеет, порядок важности: пункт 7 задания 1, остальное задание 1, задание 2, задание 4, задание 3). Claude проверит результат в среду; Opus-аудит нужен только для задания 2 (ядро EPG).

## Журнал
Каждую законченную ветку добавляй строкой в таблицу в `HANDOFF.md` (кто, что, ветка, что проверить).

## Экономия лимитов (важно, лимит владельца ограничен)
- Не перечитывай большие файлы целиком: ищи `grep`/`rg` по имени и читай только нужный диапазон строк. Не открывай `HANDOFF.md` и `CHECKLIST.md` повторно в каждом задании, достаточно один раз в начале.
- Не опрашивай CI часто: после push жди одним командным вызовом с паузой (цикл `sleep` до завершения), а не десятками проверок.
- Логи падения CI читай только строки с ошибками (`grep " e: "`), не целиком.
- Одно задание = одна ветка = небольшие коммиты. Закончил задание: напиши короткий отчёт и остановись. Следующее задание владелец запустит в новом чате (контекст возьмёшь из `HANDOFF.md`), так экономится лимит на повторное чтение длинной переписки.
- Не переписывай то, что можно поправить точечно. Не добавляй то, чего нет в задании.

## Правило против зацикливания (обязательно в каждом задании плеера)
Не уходи в бесконечные циклы правок. Если исправление не получилось с 1–2 попыток (сборка или тест всё ещё красные по той же причине), остановись: не пробуй третий и четвёртый вариант, не переписывай чужие куски. Запиши в отчёт: что пробовал, какая ошибка осталась (точная строка из лога), в каком файле, твоя гипотеза. Напиши: «не справился, проверь, пусть проверит Claude». Не жди зелёного CI дольше одного повторного запуска и не пересобирай без изменений. Простую задачу не превращай в разбор всей архитектуры: меняй только нужные файлы.
