## Два адреса сайта, как у SlyNet Radio (уточнение владельца)
У образца сайт публикуется ДВАЖДЫ из одного `deploy.yml`: GitHub Pages (https://tenyls.github.io/slynet-radio/) и Cloudflare Pages (https://slynet-radio.pages.dev/). Делай так же:
- GitHub Pages нового репозитория (адрес вида `https://eai-apps.github.io/YAiPlay-Radio/`): служебный. На нём остаются обновления приложения (`app/bundle-<id>.zip`, `version.json` Capgo), каталог для приложений, политика конфиденциальности. Включить: GitHub → eai-apps/YAiPlay-Radio → Settings → Pages → Build and deployment → Source: GitHub Actions. На бесплатном тарифе GitHub Pages работает для публичного репозитория (если репозиторий приватный, скажи владельцу).
- Cloudflare Pages (`<имя>.pages.dev`): публичный, ТОЛЬКО он в рекламе, постах, постерах, QR и подписях (правило образца).
- Оба адреса отдают один и тот же собранный сайт. Приложение и сервер должны знать оба адреса так же, как в образце (`PUBLIC_SITE`, `SITE_URL` в `worker/index.js`, `scripts/telegram-post.mjs`, `capacitor.config.json`, `vite.config.ts` base path). Внимание: адрес GitHub содержит имя аккаунта (eai-apps); не светить его в рекламе.
- В `deploy.yml` образца уже есть шаг публикации в Cloudflare (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, переменные `CF_PAGES_PROJECT`, `CF_WORKER_NAME`); перенеси его и убедись, что пути (`base`) корректны для обоих адресов.

## Как общаться с владельцем и как называть секреты (обязательно в каждом чате)
**Владелец новичок.** В каждом чате, когда нужно сделать что-то руками (создать токен, секрет, KV, ключ подписи, включить Pages), пиши инструкцию **с самого начала и по кнопкам**: какой сайт открыть, что нажать слева/сверху, как называется кнопка, что вписать, что должно появиться на экране. Не сокращай до «добавь секрет X». После каждого ручного шага попроси подтвердить результат (словами, без показа самих токенов).
**Ключи и токены он вводит сам.** Никогда не проси прислать значение, не пиши значения в репозиторий, в логи и в отчёты. Можно просить только имена секретов и подтверждение «внёс».
**Токенов уже много. Не создавай дубликаты.** У владельца уже есть несколько Telegram-ботов и ключей в GitHub и Cloudflare (бот новостей плеера, бот-ворота скачивания, бот Алисы, бот радио SlyNet и другие), а также Gemini-ключ. Поэтому:
1. Перед тем как просить создать или внести секрет, **спроси**, какие у него уже есть, и покажи, где посмотреть: GitHub → репозиторий → Settings → Secrets and variables → Actions (там видны только имена); Cloudflare → Workers & Pages → нужный Worker → Settings → Variables and Secrets.
2. Имена секретов в репозитории радио оставляй как в образце и по назначению (`TELEGRAM_BOT_TOKEN` = токен @YAiPlayer_bot, `TELEGRAM_CHANNEL` = `@YAiPlayer`; `GEMINI_API_KEY` = тот же ключ Gemini, что владелец уже использует, новый создавать не надо; `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; ключи Android `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`; `WINDY_API_KEY` только если веб-камеры нужны). Никаких «TOKEN_2/TOKEN_3»: один бот = одно значение токена, а в разных репозиториях и Worker'ах повторяется то же значение под тем же именем.
3. Для бота-ворот скачивания (@YAiPlayer_App_bot) токен уже лежит в его Worker `yaiplayer-bot`; для кнопки «Радио» его снова вводить не нужно.
4. В конце каждого чата выдай владельцу **таблицу «что где лежит»**: имя секрета, где хранится (GitHub репозиторий / Cloudflare Worker), для чего, и что сделать, если токен перевыпустят.
