# Радио-клон: решения владельца (дополнение к TASK-RADIO-CLONE.md)

Основное задание лежит у владельца на ПК: `G:\evvant\Projects\Projects\HANDOFF\Radio-Clone\TASK-RADIO-CLONE.md`. Здесь ответы на его раздел 3 «Вопросы», которые уже известны (09.11.2026). Остальное (название, пакет Android, иконка) Codex спрашивает у владельца.

- **GitHub:** репозиторий создан владельцем: https://github.com/eai-apps/YAiPlay-Radio (аккаунт eai-apps). Работать только в нём. Образец `tenyls/slynet-radio` читать можно, менять нельзя.
- **Cloudflare:** тот же аккаунт, где живёт YAiPlayer (dash.cloudflare.com, вход yai.media.player@gmail.com). Создать там НОВЫЕ отдельные ресурсы: свой Pages-проект (адрес `<имя>.pages.dev`, имя спроси у владельца, например `yaiplay-radio`), свой Worker и своё KV-хранилище. Не трогать существующее: Pages `yai-iptv-player`, Worker бота `yaiplayer-bot`, будущий сайт плеера. Имена ресурсов радио начинай с префикса радио, чтобы не путать.
- **Ключи:** токен Cloudflare (`CLOUDFLARE_API_TOKEN`, права только Pages и Workers этого аккаунта, не «глобальный ключ») и `CLOUDFLARE_ACCOUNT_ID` владелец создаёт и вносит сам: GitHub → eai-apps/YAiPlay-Radio → Settings → Secrets and variables → Actions → New repository secret. Cloudflare: My Profile → API Tokens → Create Token. Покажи ему, какие галочки ставить. Секреты никому не присылать и в репозиторий не писать.
- **Telegram:** по умолчанию отдельный канал и бот для радио (чтобы не смешивать с каналом плеера); владелец может решить иначе.
- **Лимиты общего аккаунта:** у бесплатного тарифа Workers/KV лимиты общие на весь аккаунт (запросы в сутки, чтения и записи KV). Радио без кэша может быстро их выбрать, поэтому: кэшируй ответы Worker (Cache API / заголовки), не пиши в KV на каждый запрос, не добавляй сырые списки IP. Статистику (D1) пока не включать. Если радио станет популярным, его переносят на отдельный аккаунт; поэтому держи всё в репозитории и не прячь настройки только в панели Cloudflare.
- **Связь с плеером:** позже страница радио откроется из приложения YAiPlayer (рядом с «Пультом»). Сайт плеера будет в этом же аккаунте Cloudflare, но отдельным проектом.

## Два адреса сайта, как у SlyNet Radio (уточнение владельца)
У образца сайт публикуется ДВАЖДЫ из одного `deploy.yml`: GitHub Pages (https://tenyls.github.io/slynet-radio/) и Cloudflare Pages (https://slynet-radio.pages.dev/). Делай так же:
- GitHub Pages нового репозитория (адрес вида `https://eai-apps.github.io/YAiPlay-Radio/`): служебный. На нём остаются обновления приложения (`app/bundle-<id>.zip`, `version.json` Capgo), каталог для приложений, политика конфиденциальности. Включить: GitHub → eai-apps/YAiPlay-Radio → Settings → Pages → Build and deployment → Source: GitHub Actions. На бесплатном тарифе GitHub Pages работает для публичного репозитория (если репозиторий приватный, скажи владельцу).
- Cloudflare Pages (`<имя>.pages.dev`): публичный, ТОЛЬКО он в рекламе, постах, постерах, QR и подписях (правило образца).
- Оба адреса отдают один и тот же собранный сайт. Приложение и сервер должны знать оба адреса так же, как в образце (`PUBLIC_SITE`, `SITE_URL` в `worker/index.js`, `scripts/telegram-post.mjs`, `capacitor.config.json`, `vite.config.ts` base path). Внимание: адрес GitHub содержит имя аккаунта (eai-apps); не светить его в рекламе.
- В `deploy.yml` образца уже есть шаг публикации в Cloudflare (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, переменные `CF_PAGES_PROJECT`, `CF_WORKER_NAME`); перенеси его и убедись, что пути (`base`) корректны для обоих адресов.
